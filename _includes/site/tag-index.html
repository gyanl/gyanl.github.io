{%- comment -%} Every tag that has posts, each linking to its own page. Built from site.tags — the same map the tag pages themselves read — so this index cannot drift from what those pages will actually list. Sorting a hash in Liquid yields [key, value] pairs ordered by key, so tag[0] is the name and tag[1] the posts carrying it. The count is of VISIBLE posts, not of site.tags[tag].size — and NOT because the tag page would decline to show the rest; since show_hidden it lists them all. It is because this index is the browse list, and an unlisted post is one kept out of browsing: a tag carried only by unlisted posts advertising itself here, with a count, would put the whole thread back in front of exactly the reader it was taken away from. Such a tag drops out of the index altogether. Its page is still there, still full, and still reached from the tag chips on the posts themselves and from search. Every tag here needs a matching tag/.md stub or its link 404s; that is a standing rule of the site, see CLAUDE.md. Nothing filters the list against the stubs, because Liquid cannot test for a file — adding a tag to a post means adding the stub, and this index is where a missing one shows up first. {%- endcomment -%}
{%- assign sorted_tags = site.tags | sort %} {%- for tag in sorted_tags %} {%- assign shown = tag[1] | where_exp: "post", "post.hidden != true" %} {%- if shown.size > 0 %} {{ tag[0] }}{{ shown.size }} {%- endif %} {%- endfor %}
