{%- comment -%} Tenths of a mark unit; must match baseStroke in animate-g-logo.js. {%- endcomment -%}
{%- comment -%} Dedicated scroll runway for the g-logo reveal. animate-g-logo.js measures this element and maps scrollY across it onto the mask, so the effect needs the full height of scrolling before any content arrives. This has to be its own sized element — as a margin on .container it collapsed and got clobbered by the mobile override, which left the reveal with no runway at all. {%- endcomment -%}
{%- comment -%} The hero mark. The path data lives here, not in the JS, and ships with its resting dash state already applied — iOS Safari paints the SVG before DOMContentLoaded fires, so a path that only gets its dasharray from script flashes fully drawn for a frame first. It is ONE subpath. assets/g-logo.svg authors the mark as three that all start at the same anchor, which a dash draws with two pen teleports; here the hook runs into the lower loop into the outer circle, so the pen never lifts. Written to start at the hook's tip so the reveal runs forward with a POSITIVE stroke-dashoffset — WebKit does not treat a negative offset the way Blink does, and reversed the trace on iOS. {%- endcomment -%}

Both live in .hero-spacer and are absolutely positioned there, so they scroll together as one unit — the blob is a child of the greeting, sized in em, so it tracks the type at any viewport rather than needing its own scaling. {%- endcomment -%}
